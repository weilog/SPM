## 交互说明

工作台中的故事、任务、计划项和用例单击聚焦。原详情及编辑能力通过明确的“查看详情”等按钮访问；工作台外的原有入口继续保留。

默认只高亮关联对象，不隐藏无关对象。关联筛选是用户显式操作。直接关联对应实际业务关系；间接关联给出跳数和路径。追踪避免沿同类对象回流，例如不把“任务→共享故事→其他任务”当作该任务的直接关系。

任务负责人和计划负责人独立。改故事状态不改变任务/计划状态；改计划日期不改其他计划；编辑时序场景不写任何任务状态或业务日期。

## 增量数据和接口

新增迁移：`apps/api/prisma/migrations/202610240002_workbench_sequences/migration.sql`。

仅新增 `UmlSequence`、`UmlSequenceStory`、`UmlSequenceUseCase` 三表；参与者和有序消息属于场景文档，以经过服务端验证的 JSON 保存。新表关联使用项目复合外键。没有修改旧业务列、原用例节点种类、故事状态枚举或已有多对多关系。旧项目默认时序场景为空，不导入原型演示内容。

接口前缀：`/api/projects/:projectId`。

- `GET/POST /uml-sequences`
- `PATCH /uml-sequences/:id`：更新要求匹配当前 revision。
- `DELETE /uml-sequences/:id?revision=N`：删除要求匹配当前 revision，仅删除场景及自身关联。
- `GET /relations/resolve?mode=trace&entityType=...&entityId=...`：新增成员、阶段和时序焦点，返回关系路径和分组 ID；旧调用不带 mode 时保留原有行为。
- 原项目 SSE 修订信号纳入时序场景，沿用会话有效性与项目权限检查。
- `PATCH /tasks/:id/assignee`：兼容性增加可选 revision，新界面始终提交版本。

写权限按项目经理角色校验；普通成员只读时序设计，任务关系仍按本人授权范围过滤。非法参与者/消息引用、跨项目故事/用例链接、版本冲突均被拒绝。

## 升级与启动

部署或在现有数据库启用本次版本前，备份数据库并使用正常增量升级流程：

```powershell
pnpm install --frozen-lockfile
pnpm db:generate
pnpm db:migrate
pnpm build
pnpm dev
```

无需 reset、删除旧表或重建项目。迁移是前后端配套升级的前提；旧数据库未迁移时，不应只更新前端。

本轮自动化验收使用本机 Docker PostgreSQL 上的随机隔离 schema，结束后清理测试 schema，没有对默认 public schema 执行迁移或填充演示项目。`.env` 为本机新生成的私有配置，未纳入交付文件。
