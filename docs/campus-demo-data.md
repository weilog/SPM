# 校园业务模拟数据 V1

本套数据落实已确认的“一个主项目 + 三个辅助项目”设计，增量导入，保留所有旧项目与账号。不修改业务 UI、接口或数据库结构，也不生成预制 AI 报告。

## 使用

已有本地依赖、生成客户端、后端构建和已迁移数据库时，在仓库根目录运行：

```powershell
pnpm db:seed:campus
```

全新环境先按仓库说明配置后端 `.env`，运行 `pnpm install --frozen-lockfile`、`pnpm db:generate`、`pnpm db:migrate`，构建 `@spm/shared` 和 `@spm/api`。数据库只允许本地 localhost / 127.0.0.1。

首次导入以北京时间当天作为基准日，也可在 PowerShell 设置 `$env:DEMO_BASE_DATE='2026-10-25'` 指定复现日期。重复导入跳过已有模板，既不移动日期，也不覆盖后续编辑。账号、邮件或非模板项目重名时停止；整个导入使用事务。

导入清单写入忽略提交的 `.runtime/campus-demo.json`。新旧模板分别使用 `campus_`、`tpl_` 前缀，避免覆盖原测试身份。

## 项目与数量

| 项目 | 用途 |
|---|---|
| 校园活动协作平台 · 秋季上线 | 发布、报名、签到、统计完整主流程 |
| 图书馆预约系统 · 完成交付示例 | 3 条需求、故事、任务与计划，任务均完成 |
| 社团资料归档平台 · 初始空项目 | 仅有项目和成员，用于空状态 |
| 教务内部审批平台 · 隔离示例 | 仅第二位经理获授权，含一条内部需求 |

主项目包含：24 条需求（4 一级、8 二级、12 三级）、3 产品目标、6 Epic、14 故事、32 个未归档任务（完成 10、进行中 12、待处理 10），另有 2 个归档任务；5 阶段、20 个计划工作项、5 个里程碑；7 名成员；6 个目录、12 个有实际文件内容的文档；2 张 UML 图。

计划与任务独立，通过 24 条 TaskPlanReference 关联。32 个未归档任务中有 8 个尚未关联计划：其中“梳理报名取消边界条件”和“补充统计导出验收标准”为重点待评审项，其他为后续待规划工作。不是将计划与任务复制为同一对象。

## 业务场景与事实边界

| 场景 | 数据证据 |
|---|---|
| 正常交付 | 活动发布相关任务已完成，发布评审文档齐全 |
| 需求未覆盖 | “报名取消规则”没有故事关联 |
| 验收标准不足 | “统计结果导出”验收标准为空，会议纪要明确尚未确定字段与权限 |
| 计划超期 | “完成报名资格与名额联调”在基准日前两天结束，状态仍进行中 |
| 状态不一致 | 签到联调计划为完成，关联任务仍在进行中 |
| 工作集中 | 后端有多项高优先级进行中任务，多个本人计划日期重叠 |
| 待分配 | “梳理报名取消边界条件”未分配负责人，尚未关联计划 |
| 历史记录 | 两条已归档任务，保留创建、进度与归档事件 |

规则测试验证现有规则能检出超期、重叠、集中、未分配、未规划及需求未覆盖。签到状态不一致、导出口径争议是可供人工及模型分析的证据，不声称已有独立确定性规则覆盖这两类问题。不虚构任务原生截止日期、工时容量、依赖、关键路径或精确延期概率。
