# 《爱管理》七页 AI 化统一设计与 Codex 开发规格 V2.0

> 状态：高保真整合 HTML 已生成；此文档用于负责人审核及后续 Codex 落地。**本阶段没有修改 SPM Git 仓库**。HTML 内所有 AI 分析、报告、权限、事务提交、跨业务更新均为浏览器端演示，不等于真实功能已实现。

## 1. 基线、模块边界与统一约束

- 仓库：`weilog/SPM`；读取/参考分支：`feat/s2-owner-a-integration`，并核对了 B 业务页面与 A 集成界面截图。
- 全局外壳保持 56px 顶栏、224px 浅色侧栏、已有导航、面包屑、项目上下文与权限。现有业务 UI 不做重构。
- 七个 AI 场景分布于 **五个原有导航项中的七个业务视图**：①项目概览；②需求管理；③需求管理内「故事地图」Tab；④任务管理；⑤项目计划内「甘特图」Tab；⑥项目计划内「成员任务跟踪」Tab；⑦多视图工作台。**不能把故事地图或成员任务跟踪重复加成新的一级导航。**
- 所有 AI 动作以手动触发为主。规则事实、模型推断与人工建议须独立标识；AI 不得自动更新正式数据，不得绕过后端权限。
- 使用同一套已存在的项目、需求、故事、任务、计划项、用例和成员实体；AI 报告仅存实体 ID 与必要快照，不另建平行业务对象。
- 当前 HTML 的全局验收导航属于**原型辅助控件**，不纳入正式系统。

## 2. 七页具体开发范围

### ① 项目概览：AI 健康诊断
- **原有组件**：`apps/web/src/ProjectOverview.tsx`；保留需求/任务/成员三张统计卡、项目基本信息、六个快捷入口、最近工作。
- **唯一增量**：三张统计卡下增加横向 AI 健康诊断摘要卡片；右侧约 600px 抽屉，四维 Tab 为进度风险、计划风险、任务分配风险、人员负载风险，并可在抽屉内部查看历史报告。
- **触发**：项目经理主动点击开始/重新诊断；普通成员仅能有限查看已授权结果。诊断状态为未诊断、诊断中、已完成、无风险、部分成功、失败、已过期。
- **事实**：Task 负责人/状态/进度、TaskPlanReference、PlanStage/PlanItem 日期、ProjectMember 等。当前 Task 没有独立 deadline 字段；未绑定计划项的任务不能计算逾期。无工时容量，不能声称准确利用率。
- **结果**：异常事实+证据+AI解释+建议+真实对象定位；同一底层事件可以在多维度出现，但总风险按事件 ID 去重。
- **持久化**：建议新增带数据版本/权限隔离的 `AiAnalysisRun`/`AiRiskFinding` 等模型；不可依赖浏览器内存作为真实持久化。

### ② 需求管理：AI 智能需求规划
- **原有组件**：`apps/web/src/Requirements.tsx`、`StoryViews.tsx` 及原有新建/编辑/详情逻辑。保留原五列表头：ID、需求标题、关联用户故事、更新时间、操作；原三个 Tab 与需求树、搜索、筛选、刷新、全部展开/收起均保留。
- **入口**：工具栏「AI 智能规划」从零规划；已有正式需求详情「AI 分析已有需求」自动带入当前可访问数据。共用需求管理模块内部的独立 AI 规划工作区。
- **生成**：正式需求、1–3 层自适应子需求、验收条件、用户故事、候选 Epic、实施任务及关联建议。
- **审核**：左侧树/分类、右侧可编辑字段、逐项创建/复用/跳过、疑似重复提示；不得把用户故事作为正式需求子节点存储。优先关联最具体适用需求；Epic 优先复用。
- **提交**：后端统一校验对象存在性、同项目权限、关联完整性、无环父子层级、乐观锁版本；使用 Prisma/PostgreSQL 单事务提交，失败整体回滚。任务允许 TODO 且负责人为空；不自动设完成日期或计划关联。草稿手动保存、恢复时复核引用、未保存离开提醒；生成异常不能覆盖人工编辑。
- **数据差异**：当前 `Requirement` 模型不存在独立 `acceptanceCriteria` 字段。首版 AI 建议的需求验收条件需明确决定是新增字段、扩展业务模型，还是暂作为候选文本；**不能假设数据库已有该字段**。

### ③ 故事地图：AI 关联与需求覆盖
- **原有位置**：需求管理 → 故事地图 Tab，`Requirements.tsx` 与 `StoryViews.tsx`，产品目标横向卡片 + 两列 Epic 故事卡片。
- **新增**：故事地图工具栏「AI 覆盖检查」、故事卡片低干扰提示、右侧分析抽屉。
- **事实**：Requirement、ProductGoal、Epic、UserStory、StoryRequirement、StoryTask；区分父级需求与叶子需求，统计口径与分母明示。
- **AI**：未关联需求、疑似故事重复、需求/故事/Epic 语义不匹配、验收覆盖不充分、候选补充故事。覆盖语义结论不能当作确定性真实覆盖率。
- **人工处理**：定位需求或故事；建议建立关联、生成候选故事或补充验收；必须人工确认；复用第②页审核机制。

### ④ 任务管理：AI 拆分与执行建议
- **原有组件**：`TaskWorkspace.tsx`、`TaskActions.tsx`、`MemberTaskGraph.tsx`。保留四张统计卡、任务列表/成员任务图 Tab、任务表字段、完整三点菜单与归档管理。
- **入口**：列表工具栏「AI 任务建议」，以及单条任务详情或操作菜单中的「AI 执行建议」。
- **能力**：依据任务描述、优先级、状态、完成进度、故事关联、计划项关联、历史日志给出待核查的执行建议，并生成人工审核的独立候选任务。只对 Task 有真实安排时做计划日期分析。
- **边界**：当前 Task **没有 `parentId`**，不可伪造父子任务层级；候选拆分默认创建独立 TODO 任务，负责人可为空；是否关联故事或计划由有权限的用户逐项确认。

### ⑤ 项目计划 / 甘特图：AI 进度风险与方案推演
- **原有组件**：`PlanView.tsx`、`PlanGantt.tsx`、`a-plan.css`。保留左侧四阶段树、概览/列表/看板/甘特图/成员任务跟踪五 Tab、计划项/里程碑、日期轴及原有拖动与缩放。
- **入口**：甘特图工具栏「AI 风险与推演」、日期条旁低干扰风险提示，右侧风险抽屉。
- **事实**：`PlanStage.start/end`、`PlanItem.kind/start/end/status`、`TaskPlanReference`、关联 Task；检查跨阶段越界、已到期未完成、邻近里程碑与需要复核的日期重叠。
- **推演**：多个候选方案与基线比较，显示每个计划项的原始与候选日期差异、潜在冲突、不确定条件。推演独立于正式计划数据；人工进入已有编辑器后才能保存；应使用修订号进行并发保护。
- **禁止**：未建模的任务依赖/关键路径、精确延期概率、真实工时容量均不可推断为既成事实。

### ⑥ 项目计划 / 成员任务跟踪：AI 集中度与瓶颈
- **原有组件**：`PlanView.tsx` 内 `view==='members'` 的 `member-v32`。这与「任务管理 → 成员任务图」是**不同视图**，不能相互替换。
- **原有表格**：成员/任务标题、关联任务 ID、优先级、预计开始、预计结束、计划项状态；保留相关成员/关联任务/进行中计划项三项统计及所有筛选、展开收起。
- **新增**：右上「AI 负载与瓶颈」入口、成员分组提示、分析抽屉。
- **计算**：仅使用授权的关联任务，先按 Task ID 去重再统计；区分 Task 的真实负责人和 PlanItem 的计划负责人。日期重叠与高优先级集中是待核查信号，不等于已超负荷；不得显示未经依据的百分比利用率。
- **处理**：定位 Task 详情/PlanItem 和甘特图，由项目经理人工处理，AI 不自动重分配。

### ⑦ 多视图工作台：AI 跨视图关系证据与定位
- **原有组件**：`Workbench.tsx`、`Requirements.tsx`、`PlanView.tsx`、`MemberTaskGraph.tsx`、`UmlView.tsx`；保留五 Tab、单/双视图切换、右侧视图选择、三组快捷组合、当前关联焦点及双向高亮。
- **已有接口**：`GET /projects/:projectId/relations/resolve?entityType=...&entityId=...`；返回 `ResolvedRelations`，包含 `stories`、`tasks`、`planItems`、`umlUseCases`。支持跨视图关系定位，但**没有直接返回 requirement IDs**。
- **新增**：工作台「AI 跨视图分析」入口、风险抽屉、关联证据、跨视图精准定位。需要额外使用 StoryRequirement 获取正式需求关联，按对象ID而不是标题匹配。
- **权限**：既有解析服务会限制普通成员可访问的任务；AI 结果需沿用此原则，不通过文本摘要泄露无权访问的信息。
- **禁止**：业务关联不等于因果、依赖、关键路径。跨视图结果要注明直接关联还是多跳可达。

## 3. 统一 AI 服务架构建议（后续开发阶段）

1. **授权数据上下文服务**：从已有项目 ACL 和仓库 API 读取最小必要业务快照；遵循按项目、按用户的读取权限。全局管理员未经加入不得自动访问项目。
2. **确定性规则层**：日期、状态、关联完整性、成员归属、同项目一致性、去重、对象有效性；输出明确 Rule ID 与 evidence records。
3. **AI 解读层**：只在用户点击后调用大模型，基于规则与授权上下文解释原因、提出可操作建议；任何模型输出不能作为唯一的业务事实。
4. **报告持久化**：保存 request/runId、projectId、actorId、source revision/snapshot hash、检查范围、报告状态、结构化证据/结论、生成时间；支持过时报告提示、分页历史、权限过滤、失败重试和调用预算。
5. **人工审批执行**：统一候选动作审核模型；业务修改严格走原业务 API、权限及版本/事务校验；必要时将审核记录写入审计日志。
6. **跨视图定位**：复用 Workbench 当前 `ViewFocus`、`ResolvedRelations`，并设计授权的定位 API。数据更新依赖仓库已有 SSE 与 ProjectProvider 刷新机制，避免重复订阅风暴。
7. **性能/异常**：请求去重、手动限流、超时、错误码分类、模型输出格式验证、风险列表分页；AI 故障不可影响正常需求/任务/甘特操作。

> 建议新增接口路径可采用 `POST /projects/:id/ai/analyses`、`GET /projects/:id/ai/analyses/:runId`、`GET /projects/:id/ai/analyses/history`、`POST /projects/:id/ai/planning/drafts`、`POST /projects/:id/ai/planning/commit`。这些是建议设计，**当前仓库未实现**；不要让 Codex 当作已有接口调用。

## 4. 统一原型交互与已完成自查

交付 HTML：`爱管理_AI化七页面_统一交互原型_V2.0.html`（独立、无在线依赖）。打开后沿原侧栏进入五个模块，通过需求管理和项目计划中的 Tab 进入另外两页；右下「原型演示导航」提供七页快速定位，仅供验收。

主要自查覆盖：
- 1440×900 页面布局、三统计卡与需求列表五列不变；故事地图两列 Epic、任务列表七列、项目计划五 Tab 和工作台五 Tab 与双视图结构对齐。
- 健康诊断手动触发、四维切换、风险展开、同源风险去重、报告历史、无风险/部分成功/失败模式。
- 需求规划双入口、已有需求自动带入、九项 AI 候选、逐项编辑/审核、重复对象复用、关联校验、草稿保存/恢复、未保存离开提醒、模拟提交。
- 任务候选创建后与任务列表同步；甘特候选方案对比不会修改正式基线；成员表格按真实 Task ID 去重；工作台双视图焦点与跨视图定位。
- 普通成员不能发起项目级 AI 检查和修改他人任务；AI 失败不产生真实业务数据。

**已运行浏览器回归 32 项，结果全通过；另做 9 项候选审核并确认后“模拟提交”与失败状态测试，JavaScript 页面错误为 0。** 这些测试证明独立 HTML 演示行为符合预期，不是 SPM 项目后端或真实 AI 测试通过。

## 5. 尚未实现（不能误报为已完成）

- HTML 中所有「AI 报告」都是预置模拟事实、规则结果及解释，没有模型服务、真实数据查询或 PostgreSQL 存储。
- 浏览器本地存储仅用于原型草稿与报告；业务提交只修改原型当前内存，刷新页面会恢复原始业务对象。
- 原仓库的需求/任务创建编辑、计划拖拽、故事拖拽及账号管理，在此统一原型只保留入口并以说明弹窗代替完整服务实现，**应在后续集成时直接复用真实仓库组件，而非按照原型占位弹窗重做**。
- HTML 的手动权限切换、关联高亮与跨页面操作是前端演示。真实权限过滤必须在 NestJS 后端执行，事务提交必须由 Prisma/PostgreSQL 完成。
- 当前独立原型的界面依据仓库截图和组件进行设计对齐，不是仓库运行时 DOM 的复制或自动接入。正式开发前必须重新检查目标分支 HEAD，避免覆盖他人提交。

## 6. 推荐 Codex 实施顺序

先落统一 AI 授权上下文/报告基础设施与可重复测试的确定性风险规则；再做①项目概览、③故事地图、⑥成员跟踪的读报告能力；并行但隔离开发②需求规划候选/草稿/事务；随后实现④任务建议、⑤方案推演；最后整合⑦工作台风险聚合与跨视图定位，跑 Sprint 1/2 原有功能全回归及 AI 新增端到端测试。每阶段保留 A/B 已确认 UI，验收后再合并。
