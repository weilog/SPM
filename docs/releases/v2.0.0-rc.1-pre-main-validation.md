## 发现的问题：P2 成员图关联过滤后裁切选中节点

复现环境为实际浏览器 1280×720。步骤：经理进入“甘特 + 成员”双视图，搜索聚焦 T-007“定义活动”，开启“仅看关联项”。成员图从完整列表收缩为一个任务，但 `.graph-scroll` 仍保留过滤前滚动位置。

实测图框顶部 y=436.67、scrollTop=76；任务节点顶部 y=381.67，负责人节点顶部 y=382.67，两者主体都位于图框上方。选中的标签和任务信息被裁切，只能看到节点底边。见 [10-manager-readback.png](../evidence/pre-main-20261027/10-manager-readback.png) 及 [过滤后位置记录](../evidence/pre-main-20261027/member-filter-before.json)。

点击“定位关联”后可恢复：scrollTop≈9.33，任务节点顶部 y≈448.33，进入可见范围。见 [11-manual-locate.png](../evidence/pre-main-20261027/11-manual-locate.png) 与 [恢复位置记录](../evidence/pre-main-20261027/member-filter-after-locate.json)。

相关代码：`apps/web/src/Workbench.tsx:207` 的自动定位 effect 依赖焦点、关系 ID、视图组合等，但没有关联过滤状态；`MemberTaskGraph.tsx` 按过滤结果重新布局后没有调整旧滚动位置。建议仅在过滤导致布局变化时重新定位当前目标，避免恢复成“每次普通数据刷新都抢回滚动”的旧问题，并增加真实可见区域回归。

本轮只验证和报告，没有修复此问题。既有 46/46 前端、134/134 后端的通过记录继续有效，但不覆盖此真实布局裁切。
