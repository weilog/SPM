已实际读取用户提供的 `系统用户管理.html`，使用其中的内容布局、原始CSS（加作用域）、字段与交互实现 React 页面；没有嵌入原型HTML。来源指纹与1440×900对照见 [截图索引](evidence/system-users/index.html)。

## 实际接入

- 共享顶栏、224/64侧栏、登录会话与导航；系统管理员专属“系统管理 / 系统用户管理”入口。项目经理及开发/测试无入口，后端也拒绝访问。
- 用户总数、启用、禁用三张卡；用户名/真实姓名/邮箱搜索，状态筛选、清空筛选，真实数据客户端分页（每页8条）。
- 完整六列表格：用户、用户名、邮箱、账户状态、创建时间、操作。保留查看、编辑、禁用/启用。
- 居中创建/编辑弹窗，真实姓名、邮箱、初始密码、账户状态；用户名创建后在UI不可编辑。右侧用户详情抽屉，详情可进入编辑。
- 状态变更居中确认，保存失败显示真实错误；禁用立即撤销原有登录会话。当前管理员自禁用被前后端禁止，保留最后管理员保护。
- 新账号默认全局MEMBER，不授予系统角色或任何项目成员资格；原有ProjectMember及A/B权限机制不变。不引入第二套账号体系。

## 接口与迁移

复用 GET/POST `/users`、PATCH `/users/:id`。管理员DTO增加 `displayName`、`email`、创建时可选 `active`；列表和写入返回真实创建日期，绝不返回密码散列。邮箱存储为小写，唯一约束拒绝重复；非空姓名与合法邮箱经后端验证。停用/改密码延续撤销Session逻辑。

增量迁移 `202610220004_system_user_profile` 为既有User增加可空姓名、创建时间。历史行时间保持null，不用迁移时刻冒充历史创建时间；新建行默认真实时间。现有邮箱列、账号、成员、任务、计划与数据库历史保留。已应用本地库，前后既有数据比较一致；迁移回归验证Sprint1原有字段不变且历史姓名/时间为空、无schema漂移。

兼容边界：旧调用方可以不传新增资料字段，旧用户名维护及删除API继续保留；新页面按原型只提供资料编辑及账户启停，不增加删除按钮。原有用户名语法和既有密码策略未放宽；新页面用户名按原型3–30字母数字下划线。原型8位密码与当前12位规则冲突，保留12位。按用户此前要求去掉标题说明等冗余小字、原型权限切换及演示提示；原型480px详情抽屉保留。没有新增邮件发送能力。
