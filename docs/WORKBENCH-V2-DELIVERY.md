# 多视图工作台 V2.0 融合交付

本轮依据用户提供的《Codex_多视图工作台_V2.0_开发指令.md》、独立 HTML 和交接包截图实施。用户此前确认的“保留正式甘特、选择性融合”继续适用。验收日期：2026-10-24 至 2026-10-25（北京时间）。

## 基线与范围

- 基线：`feat/demo-data-package`，`c6bd2da`。该分支保留现有 A/B/AI 功能，新增五阶段数据包，但未包含工作台融合。
- 开发分支：`feat/workbench-v2-delivery`。先整合既有融合提交 `bf09e01`（本分支对应 `0712180`），再修正布局、图面适配、定位、编辑预览及刷新行为。
- 五个视图复用 `Requirements/StoryViews`、`PlanView/PlanGantt`、`MemberTaskGraph`、`UmlView`；新增 `SequenceView`。复用 `ProjectProvider`、`TaskActionsProvider` 和既有业务详情、鉴权与编辑接口。
- 正式甘特保留阶段、日/周/月、日期条、拖动与边缘调整、信息区缩放、阶段栏、编辑、里程碑等能力。没有使用 HTML 内的简化甘特替换正式组件。
- 没有合并 main。没有改写需求、任务、成员、概览及 AI 的业务模型，也没有引入 iframe、localStorage 业务存储或前端假保存。

## 本轮真实验收记录

测试数据来自独立预览 schema 的“五阶段示例”，数据库中具有真实需求、故事、计划、任务、成员与用例关联。三条时序样例通过显式可重复的补充脚本写入该示例项目，正式界面读取真实 API；没有把样例硬编码进组件。

1. **单视图与追踪：通过。** 单击计划项展示分组关联，完整详情调用原计划抽屉，关闭后追踪仍在。截图 `01-single.jpg`、`02-tracking.jpg`。
2. **甘特/成员双向联动：通过。** 默认比例 55/45；真实指针拖动曾从 55 调为 60；选择计划高亮任务/成员，选择任务反查阶段及父计划；成员反查与筛选恢复通过。截图 `03-dual.jpg`、`05-member-reverse-filter.jpg`。
3. **覆盖层状态：通过。** 两图宽度约 629.375/514.958px；覆盖前后图内滚动、缩放与焦点相同。另实测手动滚动到 1608px 后刷新仍为 1608px。结构化记录见 `browser-checks.json`。
4. **任务负责人保存、重新登录与授权：通过。** 将 T-007 从 tpl_backend 调为 tpl_frontend，任务详情和成员图同步；计划项负责人继续为 tpl_backend。新负责人重新登录后在“我的任务”中看到该任务及更新后的进度。普通成员无改负责人/编辑任务入口，直接越权请求返回 403。截图 `06-assignee-preview.jpg`、`07-assignee-saved.jpg`、`13-member-persistence.jpg`。
5. **计划日期预览与保存：通过。** 计划“定义活动”结束日期从 10-10 调为 10-11，确认框显示前后范围，确认后详情更新；任务负责人不被修改。另实际拖动正式甘特条产生预览，再取消。截图 `08-plan-date-preview.jpg`、`09-plan-date-saved.jpg`、`17-gantt-drag-preview.jpg`。
6. **无关联/未排期/未纳入计划/无权限：通过。** 搜索“恢复联调环境访问”，只看关联时甘特显示“当前焦点没有关联计划项”，成员图标明未纳入计划；无项目资格账户项目列表为 0。截图 `14-no-access.jpg`、`16-unplanned-task.jpg`。
7. **故事和 UML：通过。** 地图/看板同时聚焦 story:4，不自动打开详情；用例和时序场景通过真实关系反向定位故事。截图 `10-map-board.jpg`、`11-uml-usecase.jpg`、`12-uml-sequence.jpg`。
8. **切换项目：通过。** 带焦点和“仅看关联项”切换到空项目后，焦点消失、筛选关闭、追踪收起，不保留上个项目的内容。截图 `15-project-switch-empty.jpg`。
9. **跨用户变更与冲突：通过。** 两个独立登录会话：成员更新本人任务进度至 37%，经理 SSE 收到 changed，浏览器图面显示最新进度；旧 revision 返回 409，计划记录和故事记录保持独立。原计划 API 中嵌入的 Task 投影正常更新。见 `live-api.json`。
10. **回归：通过本轮列出的检查。** 前端完整 39 项、后端完整 134 项，包括既有权限、需求、故事、个人任务、A 模块、鉴权和 AI 测试。类型检查、生产构建与五阶段种子重复导入检查见日志。没有调用付费模型。

所有主要截图均为真实浏览器 1440×900。`18-desktop-1280.jpg` 为额外 1280×720 检查。旧 `docs/evidence/workbench-v2/` 是融合提交带来的历史证据，本轮结果只引用 `docs/evidence/workbench-v2-delivery/`，不复用历史通过数字。

## 数据库、API 与兼容性

- 增量迁移 `202610240002_workbench_sequences` 仅增加 `UmlSequence`、`UmlSequenceStory`、`UmlSequenceUseCase` 三张表；不删除旧列，不回写旧业务行。已有数据迁移兼容性由 `workbench-migration.spec.ts` 验证。
- 新增项目级 `/uml-sequences` 的读取、新建、修改、删除；管理操作校验项目权限、跨项目关联与 revision。已有用例图模型和编辑能力保留。
- 关联解析保留旧接口模式，增补 `mode=trace` 和 member/stage/sequence 类型，返回直接/间接路径。按对象类型限制路径重复，避免同一故事或负责人把无关兄弟任务误判为选中任务的子项。
- 任务改负责人提交当前修订号，服务端拒绝过期版本。任务状态与负责人、计划状态与日期、故事状态始终分别保存。
- **现有 TaskPlanReference 为多对多，继续兼容保留。** 计划编辑支持选择多项任务，避免单选控件丢失旧关联。本轮不添加“唯一主要计划项”破坏性约束；如需定义唯一主要计划，应另行确认数据清理和兼容迁移。
- 跨用户刷新复用既有 SSE：服务端约每秒计算授权项目摘要；客户端收到变化重新读取。EventSource 自动重连，窗口激活/网络恢复重新验证。不是离线协作或数据库 CDC；大项目的摘要查询成本仍需按真实规模评估。
- 本轮迁移及写入只发生在独立测试/预览 schema，没有对 public 执行迁移或种子写入。正式环境部署前需按项目既有发布流程应用增量迁移。

## 发现并修复的问题

- 当前数据分支未包含融合能力，整合时保留两个分支已有成果。
- 原固定等分、多层工具栏、900px 成员画布导致有效图面过小；改为紧凑工具区和按实际分栏宽度排布。
- 普通单击与详情编辑混在一起；改为单击聚焦、显式详情。
- 无条件数据重读引发重复自动定位；定位改为仅在焦点、关联集合或组合变化时触发，并保留图内独立滚动。
- 关联定位优先把任务及负责人带入可视区，保留上下边距，避免刚好卡在底边。
- 计划日期编辑和原甘特拖动缺少最终预览；增加前后对比确认及正确弹层层级。
- 系统减少动态效果时，旧样式 animation:none 使部分弹层停在进入状态；改为极短动画并保留结束事件。

## 执行与证据边界

运行命令：`pnpm typecheck`、`pnpm build`、`pnpm --filter @spm/web test --maxWorkers=1`、`pnpm --filter @spm/api test`、`pnpm test:demo-data`。预览启动后可运行 `node scripts/test-workbench-live.cjs`；它只允许本地地址和显式示例项目，会更新示例任务进度并创建隔离验收空项目，不用于生产数据。

需要交互样例时，先使用原有 `pnpm db:seed:demo`，再运行 `node scripts/seed-workbench-scenarios.cjs`。后者只为带模板标记的本地五阶段项目补充场景，重复执行保留已有场景和业务编辑。

前端曾在并行构建时触发原 5 秒测试超时，最终改用单工作进程运行，未延长测试超时、删除断言或降低检查。本轮同时修正新增测试里不受 Testing Library 类型支持的 exact 参数。

旧 `owner-a-browser.cjs` 和 `s2-v43-browser.cjs` 的新工具栏选择器与日期确认步骤已同步，并完成语法检查。本轮浏览器证据来自实际操作的上述流程，未把旧自动化脚本的历史全量运行结果冒充本轮运行。AI 浏览器中仅确认保留原入口，AI 业务正确性依赖本轮后端 AI 回归，不发起付费分析。

剩余限制：正式甘特仍按现有阶段浏览；用例图保留原坐标画布和缩放，窄分栏可内部滚动；任务模型没有独立排期字段，因此不展示独立任务时间条。均未以模拟数据替代。
